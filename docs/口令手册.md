# GDWPMA-AI 操作口令手册（Hermes+GDWPMA-AI 功能系统）

> 口令=对 Hermes 会话说的一句话。Hermes 自动路由到 gdwpma-agent 技能包执行。
> 口令按"借、用、管、还"业务四环节 + 系统运维五类组织，全部经实测。

## 一、系统运维口令（启停/验证/排障）

| 口令 | 动作 | 说明 |
|------|------|------|
| 启动政府债系统 | `py app.py` 前台起服（端口 5210），或 `start-gdwpma.vbs` 静默启动 | VBS 双击等效 |
| 停政府债系统 | netstat 定位 5210 监听 PID → `taskkill /F /T` | 必杀 python 子进程，杀 py 启动器留僵尸 |
| 政府债系统体检 | pytest 6 项 + E2E 28 步 + 页面巡检 | 全绿才算过 |
| 政府债系统全面审计 | 四层审计（L1脚本→L2内联→L3投票→L4干净上下文监督） | 每季度或大版本后 |

## 二、借（项目库建设与申报审核）

| 口令 | 动作 |
|------|------|
| 给XX县建一个项目：名称/类别/投资/申请额/收入 | `/api/projects` 建档 + 底稿留痕 |
| 登记XX项目的可研批复/环评/一案两书 | `/api/docs` 材料登记（PDF 自动抽文本，扫描件可 OCR） |
| 对XX项目做申报审核 | 借环节 20 条规则扫描（负面清单/三性/覆盖倍数/要件/一案两书…） |
| 出XX项目的审核报告 | MD+DOCX+PDF 三格式，含 P0/P1/P2 分级结论与整改要求 |

## 三、发（发行管理）

| 口令 | 对XX项目做发行审核 |
|------|-------------------|
| 动作 | 发环节 14 条规则：额度与预算程序、信息披露 5 个工作日、评级报告有效性、专户管理、发行超规模、备付金制度… |

## 四、用（资金使用监管）

| 口令 | 对XX项目做使用审核 |
|------|-------------------|
| 动作 | 用环节 12 条规则：挪用/挤占截留、资金闲置超期、超进度拨付、支付流程、用途调整程序、账务处理… |

## 五、还（收入归集与偿还）

| 口令 | 对XX项目做偿还审核 / 登记还本付息 |
|------|----------------------------------|
| 动作 | 还环节 10 条规则：收入未及时收缴、收益挪用、备付金不足、到期偿付风险、资产未登记、虚假化债迹象… |

## 六、管（问题台账·整改·培训·归档）

| 口令 | 动作 |
|------|------|
| 看XX县的问题台账 | 按县市/状态筛选，分县市分布统计 |
| XX问题提交整改计划/结果 | 状态机：待整改→整改中→待复核→已闭环/已退回 |
| 对XX问题二次复核 | 复核通过闭环 / 退回重改 |
| 出本月培训要点 | 高频问题 TOP 自动聚合（台账统计） |
| 问法规：… | GLM-5.3-flash × 24部法规 RAG 问答（超纲诚实拒答） |
| XX项目立卷归档 | 全过程底稿+报告+附件打包，生成卷内目录 |

## 口令设计原则（为什么这样设）

1. **按业务环节命名，不按技术路由命名**——财政干部说"做申报审核"，不说"调 /api/review/run"。
2. **每条口令有唯一落点**（一个 API/一个流程），无歧义可自动路由；Hermes 靠 gdwpma-agent 技能包里的映射表路由。
3. **审核类口令一律触发"规则引擎→报告→台账"全链路**，而不是单点查询——与"全过程留底稿"的业务要求一致。
4. **危险动作（删除用户、重置密码）口令中显式带对象**，且仅管理员角色生效（系统强制，非口令约定）。
